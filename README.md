# PDF OCR 双层文档工具 + PDF 工具箱

单文件 Python 桌面程序（tkinter 中文 GUI），两大能力：

1. **OCR 双层 PDF**：对单层 PDF（纯图片扫描件）做 OCR，在原页面之上叠加**不可见文本层**，输出可被 Adobe Reader 等工具全文检索的双层可搜索 PDF。
2. **PDF 工具箱**：18 个常用 PDF 操作（提取文本/图片/表格、合并、拆分、旋转、裁剪、水印、页码、压缩、加密解密、涂黑脱敏、签名、书签等），支持批量处理与报告输出。

全部功能仅依赖 PyMuPDF + Pillow + numpy，不引入 pypdf/pdfplumber/reportlab 等额外库。

## 核心原理

- **底层**：原始 PDF 页面内容原样保留（矢量/图片不重新编码，画质无损）。
- **上层**：OCR 识别出的文字以 PDF 规范的 **Tr 3 不可见渲染模式**写入，位置与字号按识别框对齐。
- OCR 识别时才把页面渲染成位图，识别完立即释放，**不把位图写回 PDF**（因此不会二次压缩失真）。
- 覆盖模式采用「写临时文件 → 原子替换」，避免中途失败损坏原文件。
- 工具箱所有操作统一「输出到独立文件」，不修改源文件。

## 快速开始

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install rapidocr-onnxruntime   # 或改用 PaddleOCR / EasyOCR
python src/pdf_ocr_desktop.py
```

## 自检

```bash
python src/selftest.py          # OCR 双层 PDF 全流程（生成测试件 → 识别 → 校验可搜索性）
python src/selftest_tools.py    # PDF 工具箱 18 个工具全量验证（40 项断言，含内存防护）
python src/stress_test.py       # 大文件压力测试（多页 / 超大页面 / 超高分辨率图片）
```

## 大文件与内存安全

程序内置多层保护，**大文件不会导致崩溃**：

| 风险场景 | 保护机制 |
| --- | --- |
| 大尺寸页面高 DPI 渲染（如 A0@600dpi 需 1.6GB 单页位图） | 渲染前按页面尺寸反推**安全 DPI**，超预算自动降级并记日志 |
| 位图 + PIL + numpy + OCR 内部拷贝叠加 | 逐页显式释放（渲染完成立即丢弃 pixmap），不累积 |
| PIL 解码超大内嵌图片（数百 MB） | 超像素预算时用 **JPEG draft 在线降采样**；非 JPEG 大图直接跳过并提示 |
| PIL 解压炸弹（>1.79 亿像素） | 捕获 `DecompressionBombError` 跳过该图，任务继续 |
| 超长任务日志撑爆界面 | 日志区保留上限 4000 行，超出自动裁剪头部；队列积压时丢弃进度消息 |
| 保存失败留下半个 PDF | 任何异常都清理 `.tmp` 残留，覆盖模式仍为原子替换 |
| 内存仍不足（极端情况） | 捕获 `MemoryError` 并转为可读错误，标记该文件失败，任务继续 |

**「单页像素上限」（默认 45 MP）** 是核心安全阀：

| 页面 | 请求 DPI | 实际 DPI | 单页峰值内存 |
| --- | --- | --- | --- |
| A4 | 600 | 600 | 398 MB |
| A3 | 600 | 482 | 514 MB |
| A2 | 600 | 341 | 515 MB |
| A1 | 600 | 241 | 515 MB |
| A0 | 600 | 170 | 513 MB |

未防护时 A0@600dpi 单页峰值约 **6.4 GB**，防护后稳定在 **515 MB**。设为 `0` 可关闭保护（不推荐）。

> 实测：60 页扫描件连续 OCR，峰值 RSS 1406 MB 且无逐页累积；300 页 PDF 文本提取增量 < 1 MB。

## 关键参数建议

| 场景 | 建议设置 |
| --- | --- |
| 普通扫描件 | DPI 300，灰度开，二值化关 |
| 低质量/灰底传真件 | DPI 400，二值化开（Otsu 自动阈值） |
| 噪点较多的复印件 | 灰度 + 去噪 + 二值化，最小文本高度调到 15+ |
| 检索框不贴合 | 调「字号缩放」（默认 1.0）或 X/Y 微调 |
| 只想处理部分页 | 页面范围填 `1-5,8,10-` |
| 超大图纸/海报（A2 以上） | 保持「单页像素上限」默认 45，程序会自动降 DPI |
| 页数很多的文档（数百页以上） | 先用「页面范围」或「最大页数」分批；单页耗时约 0.3–8s |
| 内存较小的机器（8GB 以下） | 把「单页像素上限」调到 20–30 |

> 文本层透明度建议保持 `0`（完全不可见）。调高会让 OCR 文字显形，仅用于调试定位。

## 打包为可执行程序

```bash
source .venv/bin/activate
pip install pyinstaller
python build.py --clean            # onefile 模式
python build.py --onedir --clean   # 目录模式（macOS 推荐）
```

**产物按平台自动区分：**

| 打包环境 | 产物 |
| --- | --- |
| macOS | `dist/PDFOCR工具`（Mach-O 可执行文件）+ `dist/PDFOCR工具.app` |
| Windows | `dist/PDFOCR工具.exe` |
| Linux | `dist/PDFOCR工具`（ELF 可执行文件） |

> ⚠️ **`.exe` 只能在 Windows 上打包。** PyInstaller 不支持交叉编译，macOS 上产出的就是 Mach-O 可执行文件和 `.app`，不存在也无法生成 `.exe`。
> 详细的 Windows 打包方式（本机 / 虚拟机 / GitHub Actions）见 **[PACKAGING.md](PACKAGING.md)**。

**打包后务必自检**（验证 OCR 模型是否成功打包）：

```bash
./dist/PDFOCR工具 --selftest                    # macOS/Linux onefile
./dist/PDFOCR工具/PDFOCR工具 --selftest         # macOS/Linux onedir
dist\PDFOCR工具.exe --selftest                  # Windows
```

全部通过会输出 `=== 自检全部通过 ✅ ===`，覆盖依赖完整性、OCR 模型加载、双层 PDF 生成与可搜索性、工具箱可用性、内存防护。

## 注意事项

- **覆盖模式不可撤销**，处理前请自行备份原文件。
- 加密 PDF 无法做 OCR（会标记失败）；解密请用工具箱的「解密 PDF」。
- 单文件异常只影响该文件，任务继续处理其余文件；顶层异常有兜底，程序不会崩溃退出。
- 工具箱的「涂黑脱敏」是真删除内容（非视觉遮盖），不可撤销。
- 「压缩 PDF」会重压缩内嵌图片（质量档位越低压缩越狠），需要保留原始画质时请取消勾选「重压缩内嵌图片」。
- macOS/Linux 用 venv 时若报 `Tcl wasn't installed properly`，需手动链接基础解释器的 Tk 资源：
  ```bash
  ln -sfn "$(python -c 'import sys;print(sys.base_prefix)')/lib/tk9.0" .venv/lib/tk9.0
  ```
- 内网/受限网络安装依赖建议走国内镜像：
  ```bash
  pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
  ```
